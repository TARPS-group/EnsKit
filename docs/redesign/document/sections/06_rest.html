9The differentiability contract

9.1The contract

  1. Every operation below the algorithm layer is differentiable with respect to every array leaf it reads. That covers operator parameters (a covariance's entries, a lengthscale inside a kernel matrix, a scale on PSDScaled), means, factor rows, particle arrays, given values and log weights. "Differentiable" means jax.grad, jax.jvp and jax.vjp return finite, correct derivatives wherever the function is smooth.
    • Degenerate-safe (finite and correct even at exactly repeated or zero singular values): IdentityPlusGram's solve_factor, inverse_sqrt and logdet, and so everything built on them. That is condition and log_density on noisy blocks, conditional maps, every update rule, LocalizedUpdateRule, and LowRankUpdate.solve/logdet.
    • Full-rank only (finite where the factorization is nonsingular, which is also where the function is defined or unique): exact-value conditioning and its density (QR), compress (QR), and LowRankUpdate.whiten (SVD).
  2. Simulators are differentiated only if they are traceable. A pure-JAX callable is differentiated by JAX like any other function. A host-side callable cannot run under a trace at all. Wrapped in maps.BlackBox, it runs under a trace and its outputs are constants: its derivative is zero by declaration. Outside a trace, a simulator's outputs are just arrays, so they are constants for any gradient computed afterwards.
  3. Stochastic operations are reparameterized. For a fixed key, sample, realize_particles(key), pushforward(·, AdditiveNoise) and the stochastic update are deterministic functions of their parameters. Their gradient is the pathwise derivative of that realization. Because the update draws noise in whitened coordinates, the dependence on \(R\) enters through \(W\) and is differentiated exactly.
  4. Discrete choices have zero derivative, explicitly. This covers keys, resampling indices, the neighbor sets chosen by localization (the taper weights inside a set are differentiable), the failure mask, and an adaptive schedule's increment, which is computed under stop_gradient because the derivative of a bisection is meaningless. The docstring of each such function says so.
  5. Drivers are Python loops. They are differentiable end to end when the simulator is traceable and the schedule is fixed (Example 15b). They are not jit-compiled as a whole, because stopping and exhaustion are host decisions.

9.2Why IdentityPlusGram needs custom derivatives

JAX's SVD derivative divides by \(\sigma_i^2-\sigma_j^2\). The outputs of IdentityPlusGram are smooth functions of \(S\) even where that gap is zero, but autodiff through the decomposition does not know that. Its three operations therefore carry custom JVP rules written in closed form:

\[ w=(I+SS^\top)^{-1}Sb:\qquad dw = M(dS\,b + S\,db) - M(dS\,S^\top + S\,dS^\top)\,w,\quad M=(I+SS^\top)^{-1}, \] \[ T=(I+SS^\top)^{-1/2}:\qquad dT = U\big(\Gamma\circ(U^\top dA\,U)\big)U^\top,\quad dA = dS\,S^\top+S\,dS^\top,\quad \Gamma_{ij}=\frac{-1}{s_is_j(s_i+s_j)},\ s_i=\sqrt{1+\sigma_i^2}, \] \[ \ell=\log\det(I+SS^\top):\qquad d\ell = 2\,\langle (I+SS^\top)^{-1}S,\ dS\rangle . \]

The second rule is the Daleckii–Krein formula [@higham2008]. For \(f(\lambda)=(1+\lambda)^{-1/2}\) the divided difference simplifies to \(\Gamma_{ij}\) above, which has neither cancellation nor a special case for repeated eigenvalues. Written as shown it needs the full \(k\times k\) basis. The shipped form works in the thin basis \(U_r\) with the projector \(P=I-U_rU_r^\top\): the cross blocks have \(\Gamma_{ic}=-1/(s_i(s_i+1))\), and the complement–complement block vanishes because \(PS=0\). The thin form agrees with the full one to \(10^{-15}\) and with finite differences to \(10^{-10}\), including at the degenerate cases below. Measured on JAX 0.10.2, as the directional derivative along a random direction:

\(S\)plain SVD, \(T\)custom, \(T\)plain SVD, gaincustom, gainfinite difference (\(T\), gain)
exactly repeated \(\sigma = (2, 2)\)nan−0.17931nan−3.5449−0.17931, −3.5449
three zero-padded columns (a masked neighborhood)nan0.90220nan6.33850.90220, 6.3385
duplicated particles (\(\sigma_{\min}\sim10^{-16}\), not exact)−0.030849−0.030849−3.3119−3.3119agree

The hazard is therefore narrower than the current contract assumed: float-generic degeneracy is harmless, and exact degeneracy is not. Exact degeneracy is exactly what localization masks and constant predicted coordinates produce.

What a zero derivative means

A gradient through a run that evaluates a black box at points depending on \(\theta\) is a partial derivative: those evaluations are held fixed. For noise hyperparameters on a fixed ensemble that is exactly the derivative wanted. Through a multi-step EKI run, it is not, because later particles depend on \(\theta\) and so do their evaluations. The user guide states this, and the evidence objectives above are chosen to avoid it.

10Weighted ensembles

Recommendation: minimal weighting in the core, and no SMC driver.

  • In:
    • Ensemble.log_weights, weights and is_weighted;
    • reweight, effective_sample_size and resample;
    • weighted mean, cov and project.
    This is about 150 lines, and every part of it is already needed. The ESS schedule computes tempering weights [@jasra2011], whose effective sample size [@kong1994] it controls. Your EKI-then-IS workflow needs a weighted ensemble type to hand back (Example 10). Reweighting a fixed ensemble is the cleanest route to prior-hyperparameter gradients with a black-box model (§9.3).
  • Out: MCMC mutation kernels and an SMC driver. These are large, opinionated and well served elsewhere, and a user's SMC loop composes the pieces above with their own kernel. An algorithms.smc module is a natural later addition (§11). Nothing in the core would change to admit it.
  • Weighted projection fails loudly when it is meaningless. \(1-\sum w^2\) is computed stably from the log weights. When it rounds to zero (one particle holds all the weight) project raises rather than returning nan.
  • Kalman updates refuse weighted ensembles. A weighted ensemble's projection is not particle-aligned, because reading particles back would divide by \(\sqrt{w_j}\). A weighted square-root update is a different estimator with its own literature. The error message tells the user to resample first.

11Extensibility

None of the following is in scope now. Each one is listed with the piece it would add and where that piece lives. In every case the import rules accept it without change.

11.1EKS and ALDI

The ensemble Kalman sampler (EKS) [@garbuno2020eks] and its affine-invariant, finite-ensemble-corrected form ALDI [@garbuno2020aldi].

These are interacting-particle Langevin dynamics, not conditioning, so they do not use kalman at all. Everything they need is in distribution and linalg: the sample cross-covariance as an operator, the prior precision through solve, and \(\hat C^{1/2}\) as the projected factor. A step reads naturally (sketch, not prototyped):

def aldi_step(key, ens, forward, y, noise_cov, prior, dt):
    """One explicit step of ALDI (EKS plus the finite-ensemble correction)."""
    ens = maps.pushforward(ens, forward, inputs="u", output="g")
    J, d = ens.n_particles, ens.dims["u"]
    C_ug, C_uu = ens.cov("u", "g"), ens.cov("u")          # operators, never formed
    drift = (C_ug.matvec(noise_cov.solve(ens["g"] - y))
             + C_uu.matvec(prior.block_cov("u").solve(ens["u"] - prior.mean("u"))))
    sqrt_C = ens.project().factor("u")                    # (d, J): C_uu = F F^T
    noise = sqrt_C.matvec(jax.random.normal(key, (J, J)))
    # ALDI's correction is (d + 1)/J with 1/J-normalized covariances; with the
    # package's J - 1 divisor it is (d + 1)/(J - 1)
    u = (ens["u"] - dt * drift + jnp.sqrt(2 * dt) * noise
         + dt * (d + 1) / (J - 1) * ens.anomalies("u"))
    return ens.assign(u=u).drop("g")

It would live in algorithms.eks, with its own state (a time and a step size instead of a level) and the existing driver machinery. A tamed or implicit variant solves with \(I+\Delta t\,\hat C\Gamma^{-1}\), which is a LowRankUpdate.

11.2Unscented Kalman inversion

Unscented Kalman inversion (UKI) [@huang2022].

Sigma points are a weighted point set whose mean weights and covariance weights differ. That is a new distribution type, SigmaPoints, with Gaussian.sigma_points(rule) to create one and project() to fit a Gaussian. maps.pushforward already only needs names, [] and assign from its input, so it accepts any such point set once that is written as a PointSet protocol. A UKI step is then exact Gaussian algebra: predict, place sigma points, push forward, project, add noise, condition. It lives in algorithms.uki.

11.3Nonlinear transport maps

Conditional sampling by measure transport [@marzouk2016], and its use in nonlinear ensemble filtering [@spantini2022].

A new sibling of kalman, enskit.transport, imports distribution and linalg. It provides fitters such as fit_triangular(particles, given=..., targets=..., basis=...) -> ConditionalMap, and an update rule, TransportRule(fitter). Its build adds the given blocks' noise to the particles (drawn as in Matheron, from the approximation's independent terms) and fits the map; the returned update applies it at each \(y^*\) it is called with. Because a rule receives the particles themselves, it drops into kalman.update, eki.run and enkf.filter unchanged. A Kalman-affine fit is the degree-1 case, which gives a built-in correctness test.

14Implementation plan

14.1Approach

  1. Build in place, one pull request at a time, with main always green. The new layers are built beside the old ones: gauss and eki keep working until algorithms.eki replaces them, and are then deleted in one pull request. There is no long-lived branch to rebase.
  2. Contract first for every new layer, as for linalg. A normative contract page is written and adversarially reviewed before the implementation, starting from the stubs in §6.
  3. The prototype is a reference, not a starting point. It skips the validation tiers, returns dense matrices where the design returns operators, and ignores the public-first ordering. Three things carry over verbatim: the derivative formulas, the regression checks from review, and the fifteen notebooks, which become acceptance tests.
  4. Every pull request follows the existing workflow.
    • Branch dev/<topic> off origin/main.
    • uv run pytest, uv run ruff check . and the warnings-as-errors docs build all pass.
    • An adversarial review pass runs before the pull request is opened. Design tensions it finds become issues; trivial defects are folded in.
    • You review and merge.
  5. Tests are ported, not rewritten from scratch. The regression tests in test_gauss.py and test_eki.py (about 5,900 lines) encode silent-failure classes and are moved to the new API, not deleted. New conformance checks (check_update_rule, check_conditional_map), count tests (whitenings per update, compilations per run), and a test that executes every notebook are added.
