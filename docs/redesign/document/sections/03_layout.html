maps and kalman are siblings. Neither imports the other. An update conditions a distribution and has no need to know how its blocks were produced, and a map produces blocks with no need to know they will be conditioned. The only module that combines a forward evaluation with an update is the algorithm layer.

4.2Import rules

  1. Downward only. distribution imports linalg. maps and kalman import distribution and linalg. algorithms imports all four. No module imports a layer above it or beside it.
  2. Leaves are leaves. toy and testing may import any layer, and nothing in the four layers or in algorithms imports them. This keeps toy problems from becoming load-bearing (the current rule, unchanged).
  3. Cross-layer chaining goes through pipe. Gaussian.pipe(maps.pushforward, …) lets user code chain an operation defined above distribution without distribution importing it. Methods on a distribution are only the operations of its own layer. See §4.4.
  4. Private modules stay private. An underscore module is imported only from inside its own package. The conditioning core needs no exception to this: it is pure linear algebra on \(I + SS^\top\), so it lives in linalg as the public operator IdentityPlusGram, used by distribution, by kalman.localize for vectorized local updates, and by anyone writing a local rule of their own.

Vocabulary goes down only, as now. A layer may name a consumer above it to justify its scope, but may not use the consumer's concepts to define its own behavior.

One word per concept, across the package. A sample is a draw from any distribution: the generic term, used wherever the subject is probability in general ("a conditional map carries samples of the joint to samples of the conditional"). A particle is an element of an Ensemble, and when an ensemble is passed where samples are expected its particles are those samples. "Particle" replaces both of today's terms, n_samples in gauss and n_members in eki, and suits weighted ensembles. Now that ensembles are a core type, it belongs to distribution. Sizes are n_particles, n_steps, n_evaluations, latent_dim and dims[name]. The names u_dim and v_dim disappear from every layer because blocks are named. Only the toy problems keep them, as constructor arguments. EKI keeps its normative terms: a run contains steps, each made of the phases evaluate and assimilate.

Replacement text for CLAUDE.md's "Layer boundaries and vocabulary" section is the table above, plus rules 1–4 of §4.2 and this paragraph. The boundary between empirical and Gaussian is no longer crossed in exactly one place; it is crossed by Ensemble.project and Gaussian.realize_particles, and both live in distribution.

Four new project rules join CLAUDE.md:

  • Mathematics in docstrings. When a function or class implements a mathematical object or operation, its docstring states it precisely in a .. math:: block of LaTeX, defining every symbol. Prose descriptions of a formula do not substitute for the formula. The stubs in §6 follow this rule.
  • American English in code, docstrings and documentation: "centering", "behavior", "neighbor", "modeling". Today's repository uses British spelling in places (CLAUDE.md itself, the contracts, the attribute centre_misfit, which becomes center_misfit); the rename PR converts them.
  • Public API first. In every module, the public classes and functions come first, in the order of the module's index table, and private helpers (underscore names) follow below them. A reader opening a file sees the interface before the machinery.
  • Cite the literature. Wherever documentation, an example or a docstring describes a method from a paper, it cites the paper. Docstrings do so in a numpydoc References section with the full reference; the user guide and the examples do so in text, with a reference list. This amends the current self-containment rule rather than replacing it: a docstring must still be complete without the paper, and the citation records where the method comes from, not where its explanation is.

4.4Chaining across layers: pipe

x.pipe(f, *args, **kwargs) is exactly f(x, *args, **kwargs), the same method that pandas and polars provide under the same name. It exists because of rule 1. maps.pushforward lives above distribution, so it cannot be a method of Gaussian without an upward import. Monkey-patching it onto the class from maps would be worse: the method would exist or not depending on what had been imported. That leaves three ways to write a chain of operations from different layers:

# nested calls: correct, but read inside out
joint = maps.pushforward(maps.pushforward(prior, observe, inputs="x", output="g"),
                         maps.AdditiveNoise(R), inputs="g", output="y")

# reassignment: explicit, no new concept
joint = maps.pushforward(prior, observe, inputs="x", output="g")
joint = maps.pushforward(joint, maps.AdditiveNoise(R), inputs="g", output="y")

# pipe: reads top to bottom like a method chain
joint = (prior
         .pipe(maps.pushforward, observe, inputs="x", output="g")
         .pipe(maps.pushforward, maps.AdditiveNoise(R), inputs="g", output="y"))

The cost of pipe is two spellings of the same program; the implementation is three lines. Typed as pipe(f: Callable[Concatenate[Self, P], R], *args: P.args, **kwargs: P.kwargs) -> R, it keeps return types for static checkers. Recommendation: keep it as optional sugar. The user guide introduces reassignment first, so pipe is never needed to read an example.

5Project-wide conventions

5.1Arrays and batching

core trailing
Every array operand is (*batch, *core): leading batch axes, core shape trailing. This is the NumPy generalized-ufunc rule and what vmap produces. Operators contract the trailing axis; M @ x never appears in an implementation.
block values
A value of block b has core shape (d_b,). Methods that conceptually take one value (condition, update's given, the values of a conditional map) require exactly that shape. A family of values is a vmap.
particles
An ensemble block is exactly (n_particles, d_b). The particles axis is a batch axis to linalg, so op.matvec(ens["x"]) applies an operator to every particle, and noise_cov.whiten(y - ens["g"]) whitens every residual.
batched evaluation
Gaussian.log_density, reweight factors and the EKI helpers accept leading batch axes and return them, as the operator layer does.
objects
Ensemble, Gaussian, maps, update rules and states are frozen pytrees with no batch axes. A pytree rebuilt with stacked leaves is a vmapped family. It reports batch_shape and refuses every method until applied under jax.vmap, exactly as operators do today. Block names, n_particles and other metadata are static fields. A field is data only if it is an array, a LinOp, a distribution, or a tuple of these.
scalars
Returned as 0-d JAX arrays, never Python floats.

5.2Randomness

  • Typed keys only (jax.random.key), checked. Raw uint32 keys are rejected because their shape makes batch_shape ambiguous.
  • Below the algorithm layer, a function that is always random takes key as its first positional argument (Gaussian.sample, dist.resample, kalman.inflate_additive). One that is random only for some configurations takes a keyword-only key= (pushforward, update, realize_particles, update rules) and raises when a needed key is missing.
  • In the algorithm layer every step function takes the key first (enkf.forecast, enkf.analysis, enkf.filter) and splits it with a fixed arity whatever is configured: EKI into (next, inflate, update), the EnKF into (next, forecast, inflate, analysis). Toggling one policy therefore never shifts another's random stream.
  • A key is consumed whole. Callers split, and nothing stores or advances a key except an algorithm state.

5.3Dtypes and failures

  • Float64 is enabled on import. Worker processes need JAX_ENABLE_X64=1.
  • All blocks of a distribution share one real floating dtype. A simulator returning a narrower float is promoted with one warning per call. Integer or complex output raises. Wider output raises with a message naming the simulator, which resolves issue #19 in the direction that issue preferred.
  • A failed particle is a non-finite row. Ensemble.all_finite finds them. kalman.update does not repair: in debug mode it raises on non-finite input. Repair is an algorithm-level policy (on_failure="repair") because it changes the estimator.

5.4Validation and errors

The four tiers carry over unchanged:

  • class definition: field declarations;
  • construction: shapes only, never reading values;
  • call: operand core shapes, unconditional and free;
  • debug mode: values, skipped on tracers.

distribution keeps its tier-4 postcondition that conditioning results are finite. The layers define no exception types of their own except UnsupportedOpError (linalg) and EKIError (algorithms). Unsupported operations raise and never fall back to dense algebra, and size guards raise before allocating. Arguments that could be swapped silently when two dimensions coincide are keyword-only.

5.5Raising instead of falling back to dense algebra

An operator advertises what it can do cheaply (whiten, solve, factor, logdet). The question is what happens when an algorithm needs an operation the operator does not provide.

Raise (the current rule)Fall back to dense algebra
Small problemsThe user calls densify(op) once and continues. There is friction, and the error message names the fix.They just work.
Large problemsCost follows from the types: code that runs, runs at the structured cost.A silent performance cliff. Densifying a diagonal of side \(10^5\) needs 80 GB; the process dies of memory exhaustion rather than raising, far from the cause.
Bugs in structureSurface immediately. A composite that loses a capability (SquareScaled.T loses solve, issue #33) is an error, not a slowdown nobody notices.Hidden: the code stays correct and becomes \(O(n^3)\) without warning.
Wrong numbersNone; nothing is computed.Possible. A dense solve of a thin PSDLowRank is nan (issue #7), and a dense route can be numerically different from the structured one.
MaintenanceOne code path per operation; every capability is designed and documented.Two code paths per operation to test.

Where the rule bites in this design:

  • Conditioning needs whiten of each given block's noise.
  • absorb, and so a Linear pushforward of a block with an independent term, needs that term's factor. A prior known only through its precision cannot be pushed through a linear map.
  • LocalizedUpdateRule needs noise that acts row by row (a diagonal, possibly scaled).
  • inflate_additive and AdditiveNoise on an ensemble need factor.

The rule stays: raise, never fall back silently. Two refinements are adopted:

  • Check capabilities when an operation starts, before any work, so the error is raised at the call that needs the capability and names it, rather than from deep inside a kernel.
  • An explicit opt-in for prototyping (adopted): with linalg.dense_fallback(max_n=2048): densifies missing capabilities with a one-time warning and keeps the size guard. It is off by default, so library code never relies on it.
