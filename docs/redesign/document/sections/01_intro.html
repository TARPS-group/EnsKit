Design proposal · pyEKI, generalized

EnsKit

A redesign of pyEKI as EnsKit (enskit): from a package that ships Ensemble Kalman Inversion into a set of building blocks for ensemble Kalman methods in general. EKI and the EnKF are shipped as algorithms assembled from those blocks, and the same blocks are exposed at every level for people building their own.

Prepared 2 October 2026 for Andrew Roberts; revised 3 October after four rounds of review; the design is settled. Every worked example and every API marked verified was run against a throwaway prototype of this design (JAX 0.10.2, float64), with closed-form checks where one exists. Items marked specified are designed but not prototyped.

1Summary

The proposal rests on five decisions. Each one is tested by the worked examples.

  1. Two distributions, both over named blocks. An Ensemble is an empirical distribution (optionally weighted). A Gaussian is a joint Gaussian held as a shared factor plus an independent term per block. Blocks are named vectors ("u", "g", "x_prev", "forcing"), so code says what it means and there is no index arithmetic. The Gaussian handles any number of blocks; the two-block form is the special case conditioning reduces to.
  2. The bridge between the two is particle alignment. Ensemble.project() returns an EnsembleGaussian, a Gaussian subclass whose latent coordinates are the particles. It can be conditioned exactly, and its particles can be read back out (realize_particles). This replaces the current GaussianJoint/EmpiricalJoint split, and the ensemble-only operations are scoped to the subclass.
  3. The two classic updates differ only in the order of two operations. The square-root update is realize after condition. The stochastic update is transport after realize: it moves the particles, which are the joint's realization. Switching is one argument, update_rule=SymmetricSquareRoot() or update_rule=Matheron(). Each rule is a factory: it builds an update from the particles, a joint Gaussian approximation and the names of the given blocks; the given values arrive when the update is called. A user-written rule is about ten lines (Example 14).
  4. Structure is exploited through the order of operations, not through special cases. Known additive noise, a linear map and a static background covariance each enter as an exact operation on the joint Gaussian, not as a flag on an update. An approximation= hook carries a modified joint into every update and driver (Example 11). Localization wraps an update rule. Pushing an ensemble's projection through AdditiveNoise gives a lower-variance estimate than pushing the ensemble itself. Example 6 measures the difference (mean squared error 6.0 against 14.0).
  5. Strict layers with imports that only go down. The layers are linalg → distribution → (maps, kalman) → algorithms. Vocabulary goes down only, so observations, time and tempering appear only in algorithms. The rule is enforced in CI.

The design also settles the questions you raised:

QuestionAnswer in this design
Is a 2-block joint Gaussian enough?No. The public Gaussian has any number of named blocks; condition(y=...) splits them into given and target, and the kernel underneath is the existing two-block whitened SVD. Smoothers, joint state and parameter estimation, and keeping (u, g, y) together all need more than two blocks (Example 13).
Wrap the simulator in a class?No wrapper is required. A simulator is any callable taking (n_particles, d_in) arrays to (n_particles, d_out). Optional classes (Linear, AdditiveNoise) carry structure, and BlackBox makes a host-side code traceable with a zero derivative.
Transport maps as an abstraction?Yes. ConditionalMap takes joint particles and a value to conditional particles. The Gaussian's affine conditional map is the first implementation; nonlinear triangular maps plug into the same protocol later.
An EmpiricalDistribution?Yes: Ensemble. pushforward(ensemble, f, ...) returns an ensemble with the output block added.
Matheron vs transform as a computational detail?A one-argument switch everywhere. They are different estimators that agree only in the linear-Gaussian case, so update_rule is required, with no default (issue #29).
Weighted ensembles?Minimal support in the core (log weights, reweight, ESS, resample, weighted projection). SMC and MCMC drivers stay outside. Kalman updates refuse weighted input (Example 10, §10).
Interfacing with outside code?Every piece is a plain function or pytree that takes and returns arrays, operators and distributions, so a user loop can interleave package steps with its own. Example 9 alternates a package update with a user-written inverse-Wishart draw.
Differentiability?Everything except simulator calls is differentiable. Simulator outputs are constants unless the simulator is traceable. Custom JVPs keep gradients finite at the degenerate spectra that make a plain SVD return nan (§9).

2Audiences and levels

The same building blocks are exposed at five levels. Each level is written using the one below it, and the drivers' own source reads like a level-3 user's code. That is the test that the lower levels are sufficient.
